# 小程序安全手册（Mini Program Security）

> 适用版本：v5.9.0 起
> 覆盖平台：微信 / 支付宝 / 抖音（字节）/ 百度 小程序，含**微信云开发**（云函数 · 云数据库 · 云存储）。
>
> ⚠️ **合规红线（不可协商）**：
> 仅测试**自有**或**已获书面授权**的小程序（含 SRC 公告范围内的资产）。
> 对第三方小程序做未授权反编译、接口调用或数据读取均属违规。
> 反编译产物仅用于授权范围内的分析，**不得公开、不得转售、不得用于攻击非授权目标**。
> 云开发越权验证必须使用**自己的测试账号**，禁止批量遍历他人数据。

---

## 0. 为什么单独成域

小程序的安全模型有一个结构性特征：**前端即源码，后端即 API**。

1. **前端代码可 100% 还原**——`.wxapkg` / `.apkg` 等包体本质是打包的 JS + 配置，
   反编译门槛极低。这意味着任何写在前端的"校验""加密""角色判断"都是透明的。
2. **没有浏览器同源边界**——所有请求由 `wx.request` 等原生 API 发出，
   不存在 CORS、Cookie 域限制，鉴权完全依赖开发者自己带的 `token`/`openid`。
   **前端带什么，后端就信什么** —— 这是小程序越权的根因。
3. **云开发把后端也交给了平台**——云函数与云数据库的权限由"权限规则"决定，
   规则写宽了（如"所有用户可读"）就是匿名可读他人集合。

一句话：**小程序 = 透明前端 + 无同源边界 + 平台托管后端**，
三件事叠起来，越权与密钥泄露成为最高频产出。

## 1. 攻击链路（四段）

```
① 取包      PC 端缓存 / 真机抓包下载 / 开发者工具
                ↓
② 还原      反编译 wxapkg / apkg → 完整 JS + app.json + 分包
                ↓
③ 提取       接口清单 / appid+appsecret / 硬编码 token / 云环境 ID / 加密逻辑
                ↓
④ 验证       接口越权（A/B 交叉）/ 云数据库越权（匿名读）/ 登录与支付逻辑
```

**每段都可独立产出**：②③ 产物是 ④ 的输入；③ 的密钥类发现本身即可提交（若能调用后端）。

## 2. 取包与还原

### 2.1 取包路径（授权目标）

| 平台 | 路径 / 方式 |
|---|---|
| 微信 PC 端 | `%USERPROFILE%\Documents\WeChat Files\Applet\<appid>\<版本号>\*.wxapkg`（首次打开后落盘） |
| 微信开发者工具 | 工具内「代码包」目录，或开发者工具的缓存目录 |
| 支付宝 | 真机 `/data/data/com.eg.android.AlipayGphone/.../*.apkg`（需 root）或抓包重放下载 |
| 抖音 / 字节 | 真机缓存目录 `.tt` 包 + `ttml` 模板 |
| 通用替代 | 抓包发现包体下载 URL，直接 HTTP 拉取（**最省事，无需 root**） |

> 抓包是取包的通用手段：小程序启动时通常有一个包体下载请求，
> 记录 URL 后直接下载即可，绕过真机文件系统权限限制。

### 2.2 反编译

| 工具 | 适用 | 说明 |
|---|---|---|
| `unveilr` | 微信 `.wxapkg` | Go 实现，单文件，支持分包与子包遍历，推荐首选 |
| `wxappUnpacker` | 微信 `.wxapkg` | Node 实现，还原 wxml/wxss/js，老牌工具 |
| `CrackMiniapp` | 微信（含云开发） | 面向云开发场景，可提取云环境配置 |
| `miniapp-unpacker` 类 | 支付宝 / 抖音 | 各平台的社区实现，还原为 js/json |

**还原后必看**：

1. `app.json` — 页面路由清单（= 前端可见的功能面）。
2. `project.config.json` / `app.js` — **`appid`、云环境 ID（`env`）**。
3. 全部 `*.js` — 接口路径、请求头构造、加密/签名函数、硬编码常量。
4. `*.wxml` / 模板 — 隐藏入口、调试页、未在菜单暴露的页面。

**grep 优先级**（还原目录内）：

```
appsecret | secret | appkey | apiKey | accessKey | AKID | privateKey
https?://[^"']+                       # 全量接口清单
wx.cloud.init | env:                  # 云开发环境 ID
code2session | session_key            # 登录链路
encryptedData | iv                    # 敏感数据解密
sign|signature|hmac|md5|sha256        # 签名算法（是否可伪造）
/admin|/manage|/internal|/debug       # 高价值路径
```

## 3. 检测清单

| 类 | 入口 | 构造法 | 判定标准（可提交） | 不可提交的反例 |
|---|---|---|---|---|
| 包还原 | 包体 | 反编译 | 拿到完整前端源码与配置 | 只拿到混淆片段、无接口信息 |
| 硬编码密钥 | 还原产物 | grep 密钥 → 调后端接口 | **密钥可实际调用后端并返回真实数据** | 仅"包里有个疑似 key 字符串"、调用返回 401 |
| 接口越权 | 接口清单 | A 的资源用 B 的 token 请求 | **A/B 交叉证明**（复用 `business_logic.py ab`） | 无凭证也 200 → 改判未授权访问 |
| 云数据库越权 | 云环境 ID + 集合名 | 直接从客户端/HTTP 匿名读写集合 | 匿名或跨用户读到他人集合数据 | "权限规则看起来宽松"、读取返回权限错误 |
| 云函数滥用 | 云函数名 | 直接 `callFunction` 传任意参数 | 越权拿到他人数据 / 触发高权动作 | 函数存在但无越权效果 |
| 登录逻辑 | `wx.login` 链路 | code 重放 / 复用他人 openid / session_key 盗用 | 登录为他人账号 / 解密出他人手机号 | code 单次失效（正常） |
| 手机号解密 | `encryptedData`+`iv`+`session_key` | 用自持 session_key 解他人密文 | 解出他人手机号 | 解密失败、拿到的是自己的号 |
| 支付逻辑 | 下单/支付/回调 | 篡改金额/订单号/`prepay_id`；重放 `notify` | 以非应付金额完成支付 / 回调可伪造 | 仅"前端存在金额字段"、未验签无实际效果 |
| 渲染注入 | 富文本 / `rich-text` | 注入标签或事件 | 真机内真实执行（截图/录屏） | 仅接口返回了标签、渲染被转义 |

## 4. 云开发专项（最高频产出）

微信云开发的权限存在三个层面，逐层查：

**4.1 云数据库权限规则**

控制台为每个集合设置四选一：

| 规则 | 含义 | 风险 |
|---|---|---|
| 仅创建者可读写 | 按 `_openid` 隔离 | 低 |
| 所有用户可读，仅创建者可写 | 登录用户可读全表 | **中高** |
| 所有用户可读，所有人可写 | 无需登录 | **严重** |
| 仅管理端可读写 | 仅云函数可访问 | 低 |

**验证方式**：拿到 `env` 与集合名后，用**自己账号**在开发者工具或小程序内
调用 `db.collection('X').get()`，观察是否返回**非自己**的文档。
匿名写入测试：`db.collection('X').add({...})` 是否成功。

> 提交要求：必须给出**读到的他人文档样本**（脱敏）与集合权限规则截图。

**4.2 云函数**

- 检查云函数是否**校验调用方身份**（很多直接 `context.OPENID` 或干脆不校验）。
- 检查是否信任入参中的 `openid` / `userId`（**前端传谁就是谁** → 越权）。
- 检查云函数内的数据库操作是否用了**管理端 SDK**（必然绕过权限规则）。

**4.3 云存储**

- `cloud://` 文件 ID 若为"所有用户可读" → 可枚举/遍历下载。
- 检查上传路径是否可穿越（`../`）、是否校验文件类型。

## 5. 登录与支付链路要点

**登录链路（`wx.login` → `code2session`）**

```
小程序 wx.login() → code → 后端带 (appid, secret, code) 请求微信
→ 返回 openid + session_key → 后端自建登录态（通常是自签 token）
```

高频缺陷：
1. 后端**直接信任前端传入的 openid**（跳过 code2session）→ 任意账号登录。
2. 自签 token 算法弱（固定密钥 / 无签名）→ 可伪造任意用户身份。
3. `session_key` 未与用户绑定或长期不轮换 → 可解他人手机号。
4. 手机号走**前端解密**（`encryptedData`/`iv` 从前端传）→ 密钥在客户端等于没有。

**支付链路**

1. 下单金额是否**服务端重新计算**（前端传金额 = 严重）。
2. `notify` 回调是否**验签**（不验签 = 可伪造支付成功）。
3. 订单号/`prepay_id` 是否可**跨用户复用**（重放支付）。
4. 退款金额是否校验（可超退）。

## 6. 与既有模块的复用

| 目标 | 复用模块 | 说明 |
|---|---|---|
| 接口越权 A/B 交叉证明 | `business_logic.py ab` / `judge` | 与 Web 越权**同一硬标准**，不另立口径 |
| 接口枚举与路径发现 | `directory_fuzzer.py` | 从还原产物拿到接口前缀后扩面 |
| 请求构造与重放 | `httpRequest` / `Bash` + `curl` | 小程序接口本质是 HTTP，普通工具即可 |
| 带外验证（回调类） | `oob_client.py` | 支付/登录回调 SSRF 场景 |
| 记忆 | `clueboard.py`（hosts/paths/keys/excluded） | 小程序包信息写 `keys` 区块（**脱敏**） |
| 交付 | `report_docx.py` | 走同一验证门 |

**关键口径统一**：小程序的"接口越权"与 Web 的 IDOR **完全同源**，
因此**必须过 `idor` 类型命门**（A 的资源用 B 的凭证读到），不得因为"是小程序"而放低标准。

## 7. 过门口径

| 类型 | 责任字段 | 说明 |
|---|---|---|
| `hardcoded_secret` | `secret_usable_proof` / `api_call_proof` | 密钥能实际调通后端 |
| `mp_api_idor` | 复用 `idor` 命门（`ab_proof` 等） | A/B 交叉证明 |
| `cloud_db_exposure` | `cross_user_proof` / `anon_read_proof` | 匿名或跨用户读到他人数据 |
| `cloud_function_abuse` | `state_change_proof` / `cross_user_proof` | 越权动作真实生效 |
| `mp_login_logic` | `ato_proof` / `arbitrary_user_proof` | 任意用户可登录/接管 |
| `mp_payment_logic` | `state_change_proof` / `payment_proof` | 以非应付金额完成支付 |

## 8. 合规与清理

1. 反编译产物（`unpacked/`）**不入库**、不进线索板原样粘贴，只记脱敏结论。
2. `appsecret`、`session_key`、他人手机号等敏感值入板时**必须脱敏**，原始值放
   `hunts/<目标>/raw/`（该目录不共享）。
3. 云数据库测试**只读、限定条数**（`limit(5)`），禁止全量遍历与导出。
4. 测试完成后清理：删除测试期间写入的集合文档、上传的测试文件。
